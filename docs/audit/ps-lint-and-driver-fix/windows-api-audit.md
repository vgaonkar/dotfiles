# Windows API Verification Audit — `fix-stuck-driver-update.ps1`

> Read-only research audit. No script files were modified. This document verifies
> every Windows-specific API claim in `windows/scripts/fix-stuck-driver-update.ps1`
> against official Microsoft documentation (learn.microsoft.com), per the standing
> rule: never guess on system behaviour, verify from a primary source and quote it.
>
> The script has never run on Windows. Everything below was checked against docs,
> not against a live machine — anything docs don't state is marked UNVERIFIABLE,
> not filled in with plausible knowledge.

## Summary of everything NOT fully confirmed

- **WRONG:** none found. Every specific syntax claim that has an authoritative Microsoft Learn page (pnputil flags, `Remove-PrinterDriver` parameter, `Get-PnpDeviceProperty`/`Get-PnpDevice` properties, `QueryHistory`/`OperationResultCode`/`IUpdateHistoryEntry`, the two registry policy paths+value names, `Get-WindowsUpdateLog` syntax) matches the script exactly.
- **UNVERIFIABLE / PARTIAL** (assumed, not verified — flagged per the standing rule):
  1. **`Get-WindowsDriver` output property names** (`Driver`, `OriginalFileName`, `ProviderName`, `ClassName`, `Version`, `Date`) — official doc only names opaque output types, doesn't enumerate properties.
  2. **`DenyDeviceIDs` subkey-with-numbered-values storage format** — confirmed key path and the boolean DWORD name officially; the actual list-storage structure the script's append logic (D7) depends on is corroborated only by non-Microsoft sources.
  3. **`WindowsUpdate\Auto Update\RebootRequired` registry path** — one of three pending-reboot signals; the other two (CBS, PendingFileRenameOperations) are corroborated via Microsoft Q&A, this one was not found in any source during this audit.
  4. **Exact real-world meaning of `0x800f020b` / `0x80070103`** — consistent across many Microsoft Q&A threads but no single canonical reference page exists; both only drive advisory text in the script, not control flow.
  5. **Five service names (`wuauserv, bits, cryptsvc, msiserver, usosvc`) existing on Windows 11**, and whether `usosvc` is "stoppable" beyond one Q&A thread describing it as *disable-blocked but stop-permitted*.
